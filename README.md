# flex-work-hours-pacer

[flex.team](https://flex.team) 근무 페이지(`내 근무` > `my-work-record`)에서, 이번 정산기간에 하루 평균 얼마나 더 일해야 하는지를 계산해서 화면에 바로 보여주는 Firefox/Chrome 브라우저 확장 프로그램입니다.

`133:03` 실근무시간 위젯 바로 아래에 `Need Xh Ym/day (Nd)` 형태로 작게 표시됩니다. 괄호 안은 남은 근무일수로, 계산이 조용히 틀렸을 때 눈으로 바로 확인하기 위한 값입니다.

## 어떻게 계산하나요

DOM을 읽지 않고 flex.team이 페이지를 그릴 때 쓰는 내부 API를 같은 오리진으로 호출합니다. 로그인 쿠키가 그대로 붙으므로 별도 인증 처리는 없습니다.

- **신원**: 쿠키 `V2_CUSTOMER_INFO`의 `userIdHash`
- **정산기간**: `work-rule/.../working-periods/by-timestamp-range` -> `startDate` / `endDateInclusive`
- **잔여 필수 근무시간**: `time-tracking/.../work-schedules/summary/by-working-period`의 `resultForFullFlexible.requiredWorkingMinutes`. 그 필드가 없는 근무제에서는 `requiredAgreedWorkingMinutes - totalRecognizedWorkingMinutes`로 같은 값을 만듭니다.
- **남은 근무일수**: 오늘(포함)부터 정산기간 종료일까지, 아래에 해당하지 않는 날을 셉니다.
  - `work-schedules/date-attributes`의 `dayOffs[].type` -> `REST_DAY`(토) / `WEEKLY_HOLIDAY`(일) / `CUSTOM_HOLIDAY`(공휴일, 대체공휴일)
  - `work-schedules`의 `timeBlocks[].type`이 `*TIME_OFF`이고 그 날 **소정근로시간을 전부 덮는** 경우 -> 종일 연차. 미래에 등록한 연차도 여기서 잡힙니다.
  - 같은 `timeBlocks`에 끝난 `WORK` 블록이 하나라도 있는 날 -> 퇴근을 찍은 날이므로 분모에서 제외. 그 시간은 이미 잔여 필수에서도 빠져 있습니다. (합계 분이 아니라 블록 존재로 봅니다. 휴게가 근무만큼 길면 합계가 0이 되는데 그 날도 이미 끝난 날입니다.)
  - 예외: 끝 타임스탬프가 없는 `WORK` 블록이 있으면 근무 중으로 보고 포함합니다.

  반차·시차처럼 하루 일부만 쓴 휴가는 **제외하지 않습니다.** 3시간 시차를 미리 등록해둔 날도 남은 5시간은 일해야 하므로 근무일로 셉니다. 그런 날에 출퇴근 기록이 찍히면(합계가 소정근로에 못 미치더라도) 하루가 마감된 것으로 보고 제외합니다.

  시차가 걸린 날도 다른 날과 같은 크기의 하루로 셉니다. 가용시간만큼 가중치를 주는(3시간 시차 = 0.625일) 방식도 되지만, 완전선택근로라 시차를 쓴 날 저녁에 더 일하는 걸 막는 게 없어서 온전한 하루로 두기로 했습니다. 온전한 하루로 세는 대신, 아래 되돌려더하기로 분자를 맞춥니다.
- **부분휴가 되돌려더하기**: 위에서 센 남은 근무일에 시차·반차가 걸려 있으면, 그 휴가 시간을 잔여 필수 근무시간에 **도로 더합니다.** flex가 휴가를 인정근무로 쳐서 잔여 필수에서 이미 빼두는데 그 날은 온전한 하루로 분모에 남기 때문입니다. 더하는 대상은 **분모에 남은 날뿐**입니다. 분모와 같은 판정 함수(`isRemainingWorkDay`)를 쓰므로 종일 연차나 이미 퇴근한 날의 휴가는 더해지지 않습니다.

  근거는 summary 응답의 항등식입니다(2026-09-23 실측): `normalWorkMinutes 7346 + nightWorkMinutes 87 + totalTimeOffMinutes 600 = totalRecognizedWorkingMinutes 8033`. `overWorkMinutes`·`holidayWorkMinutes`가 모두 0이라 저 600분은 실근무로 설명되지 않습니다. 게다가 그 600분에는 **닷새 뒤인 09-28 명절휴가 480분**이 들어 있어, 미래에 등록해둔 휴가도 즉시 반영된다는 것까지 확인됩니다. (`timeOffUseResultsByTimeOffPolicies[].totalMinutesNotRecognizedAsWork`가 0인 것은 정책이 휴가를 인정근무로 친다는 뜻일 뿐, 스냅샷에 이미 반영됐다는 근거는 아닙니다.)

- **하루 평균 필요시간(N)**: 어느 날 실제로 더 일할 시간은 `max(0, N - 그 날 휴가)`이므로, 그 합이 잔여 필수와 같아지는 N을 씁니다. 휴가가 N을 넘는 날은 그 날 더 일할 게 없다는 뜻이라 분자·분모에서 빼고 다시 구합니다. 어느 날 휴가도 N에 못 미치면 첫 계산에서 끝나고, 그 값은 `(잔여 필수 + 되돌려더한 휴가) / 남은 근무일수`와 같습니다.
- **이미 다 채웠는지는 원본 잔여 필수로 판정합니다.** 되돌려더한 값으로 보면, 목표를 넘겼는데 휴가를 앞으로 등록해둔 것만으로 `Goal met`이 "더 일해야 함"으로 뒤집힙니다.

  괄호 안 숫자는 **아직 더 일해야 하는 날의 수**입니다. 보통은 남은 근무일수와 같지만, 휴가만으로 하루 필요량이 채워진 날이 있으면 그만큼 작아집니다. 이렇게 두면 `분자 / 괄호 안 날수`가 정확히 하루 필요량이 되어 눈으로 검증하는 성질이 유지됩니다. 콘솔에는 `workDays=1/2`처럼 둘 다 찍히고, 빠진 날은 `covered=09-29:240m`으로 표시됩니다.

결과적으로 배지 숫자는 **인정근무 기준** 하루 필요량이 되어 모든 날에 같게 나옵니다. 시차를 2시간 쓴 날은 그 필요량 중 2시간이 이미 채워져 있는 셈이라, 실제로 더 일해야 하는 시간은 그만큼 적습니다.

실측 예시(2026-09-23): 잔여 필수 1291분, 09-23에 시차 120분, 남은 근무일 3일 -> `(1291 + 120) / 3 = 471분` -> `Need 7h 51m/day (3d)`. 오늘 실제로 더 일할 시간은 `471 - 120 = 351분`이고 09-29·09-30은 각 471분이라, 합이 1291분으로 맞아떨어집니다. 되돌려더하기가 없으면 `Need 7h 11m/day`가 나오는데, 시차를 뺀 오늘 가용시간(6시간)보다 큰 값을 오늘 요구하면서 전체 페이스는 낮게 잡는 숫자였습니다.

휴가가 하루 필요량을 넘는 날에는 단순 나눗셈이 깨집니다. 잔여 2시간에 남은 이틀 중 하루가 반차(4시간)면 `(120 + 240) / 2 = 3시간/일`이 나오는데, 반차 날은 이미 4시간이 채워져 있어 더 일할 게 없으니 실제로는 나머지 하루에 2시간만 채우면 됩니다. 그래서 그런 날을 빼고 다시 계산해 `Need 2h/day (1d)`로 표시합니다.

## 설치 (개발자 모드로 로컬 로드)

이 저장소는 스토어에 배포하지 않고, 로컬에서 직접 로드해서 사용하는 걸 전제로 합니다.

### Firefox

1. `about:debugging#/runtime/this-firefox` 접속
2. **"임시 부가 기능 로드..."** 클릭
3. 이 저장소의 `manifest.json` 파일 선택

### Chrome

1. `chrome://extensions` 접속
2. 우측 상단 **"개발자 모드"** 켜기
3. **"압축해제된 확장 프로그램을 로드합니다"** 클릭 → 이 저장소 폴더 선택

두 브라우저 모두 임시/개발자 모드 로드이므로, 브라우저를 재시작하면 다시 로드해야 합니다.

## 개발

순수 계산 로직(`src/pace.js`)은 Node.js 내장 테스트 러너로 테스트합니다. 외부 의존성은 없습니다.

```bash
npm test
```

`src/flex-api.js`와 `src/content.js`는 실제 flex.team 세션(쿠키, 내부 API, 지표를 끼워넣을 DOM 위치)에 의존하는 부분이라 자동화 테스트 없이, 브라우저에 로드해서 콘솔의 `[flex-pacer]` 로그로 확인합니다.

```
[flex-pacer] period=2026-09-01..2026-09-30, required=1291m, addBack=120m, remaining=1411m,
             workDays=3/3, excluded=09-24:CUSTOM_HOLIDAY ..., partialLeave=09-23:120m/480m,
             covered=, flexOwn=430m/3d
```

`workDays=`는 `하루 필요량에 쓴 날수/남은 근무일수`, `covered=`는 휴가만으로 채워져 빠진 날, `flexOwn=`은 flex 자신의 계산값입니다(계산에는 쓰지 않고 대조용으로만 찍습니다).

계산 로직 검증은 실제 API 응답을 브라우저 콘솔에서 파일로 저장해 로컬에서 돌려보는 방식으로 했습니다. 응답에는 개인 근무기록이 들어있어 저장소에 커밋하지 않고, `test/fixtures`에는 같은 모양의 합성 데이터만 둡니다.

## 파일 구조

```
manifest.json     확장 프로그램 매니페스트 (Manifest V3)
src/
  pace.js         API 응답 -> 날짜별 근무일 판정 + 하루 평균 계산 (테스트됨)
  flex-api.js     flex.team 내부 API 호출 (쿠키에서 신원 읽기 포함)
  content.js      API 호출 결과를 화면에 표시
  banner.css      표시 스타일
test/
  pace.test.js       계산/포맷 테스트
  api-days.test.js   API 응답 -> 근무일 판정 테스트
  fixtures/          실제 응답과 같은 모양의 합성 픽스처
```

## 알려진 제한사항

- **내부 API에 의존합니다.** 공개 API가 아니라 페이지가 쓰는 엔드포인트를 그대로 호출하므로, flex.team이 스키마나 경로를 바꾸면 동작하지 않습니다. 그 경우 값을 표시하지 않고 콘솔에 경고만 남깁니다.
- `resultForFullFlexible`은 완전선택근로 응답 필드입니다. 다른 근무제에서는 폴백 계산식을 쓰는데, 실제 응답으로 검증하지는 못했습니다.
- 근무 중인 하루는 `timeBlocks`가 빈 배열로 옵니다(2026-08-20 근무 중 실측). 퇴근을 찍어야 블록이 생기므로, 진행 중인 오늘은 인정근무 0으로 잡혀 자연히 남은 근무일에 포함되고 퇴근 시점에 제외됩니다. 끝 타임스탬프가 없는 `WORK` 블록을 근무 중으로 보는 처리도 남겨뒀지만, 실제로 그런 응답은 관측되지 않았습니다(방어용).
- **`totalMinutesNotRecognizedAsWork` 경고는 되돌려더하기의 전제를 검증하지 못합니다.** 이 값은 "그 휴가정책이 휴가를 인정근무로 치는가"만 알려줄 뿐, "잔여 필수 스냅샷에 이미 반영됐는가"는 말해주지 않습니다(전제의 근거는 위 항등식입니다). 다만 0이 아닌 값은 그 자체로 진짜 실패 모드입니다. 인정근무로 안 쳐주는 휴가는 잔여 필수에서 안 빠져 있는데 되돌려더하기는 더해버리기 때문입니다. 정산기간 전체 합계라 어느 날 것인지는 알 수 없어 자동 보정은 하지 않고, **이번 계산이 실제로 휴가에 기대고 있을 때만**(되돌려더한 값이 있거나 `covered`로 빠진 날이 있을 때) 경고합니다.
- **반차·시차가 걸린 날도 온전한 하루로 셉니다.** 되돌려더하기로 총량은 맞지만, 그 날 필요한 인정근무량은 다른 날과 같게 표시됩니다. 시차가 그 날 소정근로의 대부분을 덮으면 실제로 더 일할 시간은 매우 짧아지는데, 배지에는 그 사정이 드러나지 않습니다. 휴가가 하루 필요량 자체를 넘어서면 그 날은 분모에서 빠지고 괄호 안 날수가 줄어듭니다(콘솔에는 `workDays=1/2`처럼 둘 다 찍힙니다).
- 종일 휴가 판정은 `usedMinutes`가 그 날 `usualWorkingMinutes`를 덮는지로 합니다. 실측(2026-09-28 종일 휴가, 정책은 명절휴가): 블록은 `usedMinutes: 480`, `usedPaidMinutes: 480`, `restMinutes: 0`, `allDay: true`, `timeOffRegisterUnit: "DAY"`이고, 같은 날 `usualWorkingMinutes`는 480 그대로, `dayOffs`는 빈 배열입니다. 즉 flex는 휴가를 써도 소정근로시간을 깎지 않으므로 반차(240)·시차(180)는 종일로 오판되지 않습니다.
- **시차 블록 실측(2026-09-23, 2시간 시차)**: `usedMinutes: 120`으로 내려와 콘솔에 `partialLeave=09-23:120m/480m`로 정상 인식됩니다. 블록의 `allDay` 값 자체는 아직 못 봤지만 `isFullDayTimeOff`가 `usedMinutes`를 우선하므로 영향이 없습니다. 반차 블록은 여전히 미관측입니다.
- `restMinutes`가 0이 아닌 표본은 못 봤습니다. 만약 `usedMinutes`가 휴게를 뺀 값이라면(종일 연차가 `420m/480m`으로 옴) 진짜 연차가 근무일로 잡힙니다. 위 `partialLeave` 로그에 그런 근사치가 찍히면 그때 판정식을 고치면 됩니다.
- 진행 중인 오늘 근무는 flex의 인정근무/잔여 필수에 반영되지 않습니다(퇴근 후 반영). 그래서 근무 중에는 표시값이 실제보다 약간 큽니다.
- 정산기간이 두 달에 걸쳐도 API가 `startDate`/`endDateInclusive`를 주므로 문제되지 않습니다. (DOM 방식에 있던 한 달 제약이 없어졌습니다.)
